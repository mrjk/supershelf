Set variables¶

supershelf scan vars prints one row per matched file. The vars cell lists the final values. How those values are layered is in Variables.

This profile sets a default owner, then replaces the vendor on the Bank2000 statement rule. The filename regex captures date and receipt_id. Those captures are facts. The rule can read them.

profile.books.toml
[[inputs]]
path = "inbox"

[default_vars]
vendor = "UNKNOWN"
owner = "sample"

[[match_rules]]
name = "bank2000_statement"
kind = "invoice"
filename_regex = 'REL_(?P<date>\d{8})_(?P<receipt_id>\w{8})\.pdf'

[match_rules.vars]
vendor = "Bank2000"
receipt = ["{{ receipt_id }}", "UNKNOWN"]

[[match_rules]]
name = "unsorted"
glob = "**"
profile.books.yaml
inputs:
  - path: inbox

default_vars:
  vendor: UNKNOWN
  owner: sample

match_rules:
  - name: bank2000_statement
    kind: invoice
    filename_regex: 'REL_(?P<date>\d{8})_(?P<receipt_id>\w{8})\.pdf'
    vars:
      vendor: Bank2000
      receipt:
        - "{{ receipt_id }}"
        - UNKNOWN

  - name: unsorted
    glob: "**"

receipt tries {{ receipt_id }} first. If that name is missing, the next candidate, UNKNOWN, is kept. A candidate with no {{, {%, or {# is stored as written.

supershelf scan vars "Bank2000/REL_20260425_ab12cd34.pdf"

Example vars and sources cells. Internal facts are omitted unless --all is set. Names are alphabetical, and each sources line matches the name on that line.

vars                                      sources
date: 20260425                            fact
owner: sample                             default
receipt: ab12cd34                         rule:bank2000_statement
receipt_id: ab12cd34                      fact
vendor: Bank2000                          default, rule:bank2000_statement

vendor was set in default_vars and replaced by the rule, so both layers stay on its sources line. owner stays sample because the rule does not set it.

Declare a type¶

vars_schema sets the type of a name. A filename group with that name is cast when the match stores it. The rules are in Variables.

profile.books.toml
[vars_schema.amount]
type = "float"
unit = "EUR"

[[match_rules]]
name = "bank2000_amount"
kind = "invoice"
filename_regex = 'REL_(?P<amount>[0-9]+[.][0-9]{2})\.pdf'
profile.books.yaml
vars_schema:
  amount:
    type: float
    unit: EUR

match_rules:
  - name: bank2000_amount
    kind: invoice
    filename_regex: 'REL_(?P<amount>[0-9]+[.][0-9]{2})\.pdf'

For REL_12.50.pdf, the table shows amount: 12.50. In --format json and --format yaml that name is an object: value is 12.5, and value_sources lists the layers. display is not in the object. csv uses the same vars and sources cells as the table. Templates still read the string 12.50. EUR12.50 stops the file, because a regex group has no next candidate.

Print a JSON Schema¶

supershelf schema prints those declared types. It does not scan the inbox and it does not write a kind file.

supershelf schema

The output is one JSON document, keyed by profile name. Add kind_schema when a kind should require a name or carry its own description:

profile.books.toml
[kind_schema.invoice]
desc = "A vendor bill"

[kind_schema.invoice.vars_schema]
__date__ = ""
vendor = "vendor"

[kind_schema.invoice.vars_schema.amount]
schema = "amount"
mandatory = true
profile.books.yaml
kind_schema:
  invoice:
    desc: A vendor bill
    vars_schema:
      __date__:
      vendor: vendor
      amount:
        schema: amount
        mandatory: true

A string is the catalog name. Null or a blank string uses the local name. TOML has no null, so that form is "". An object may omit schema, which then uses the local name. invoice is then an object under $defs. amount is required. The rules are in Variables. A new CSV for that kind uses these local names as columns. An existing CSV gains any that are missing, on the right.

scan vars has no --quick. The walk always reads mtime, ctime, and sha256. The path argument is the same as List files. Omit it to list every matched file. If any kept path equals the selector, every input lists that exact path only. Otherwise the selector lists matched paths that start with it. A value that no kept file has stops the command. When a path is set, only the selected files are matched, so other files are not warned.

A key in one mapping cannot read a key that appears later in that same mapping. {{ vendor }} inside default_vars, next to vendor, still sees the previous layer, which is the fact scope. It does not see the candidate list being tried.
